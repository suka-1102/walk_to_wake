# Walk to Wake

「絶対に行かなければならない」を、お金の力で実現するコミットメント支援Webアプリ。

ユーザーが自分で設定した目標地点に、決めた時刻までに実際に足を運ぶ（＝チェックインする）ことを、デポジット（預り金）の減額というペナルティで後押しする。

アラームは鳴らさない。起こすのは既存のアラームアプリの役割であり、本アプリが担うのは「鳴った後、二度寝せずに外へ出る」動機付けの部分。

> **v1 の時点では実際の金銭は動かない。** Stripe による決済・返金の連携は v2 以降のスコープで、v1 はペナルティ額の計算と表示までを行う。

## コンセプト

「早起きして外に出る」こと自体が目的。目標地点は行き先そのものに意味がある場所（ジムや図書館など）である必要はなく、近所のコンビニのように「家を出て歩けば着く場所」であれば何でもよい。目が覚めて外出する行動を作ることが狙い。

1. ユーザーは目標地点（近所のコンビニなど、家を出て歩いて行ける範囲の場所）を登録する。登録は現地でブラウザの Geolocation API を使い、実際にその場所へ行って取得した座標をそのまま目標地点として記録する（地図上でピンを指定する方式ではない）
2. 毎日のチェックイン期限時刻と、チャレンジの継続期間（開始日〜終了日）を設定する
3. 期間中、毎日期限時刻までにブラウザの位置情報を使って目標地点付近でチェックインする
4. 期限に間に合わなかった／目標地点に到達しなかった日はチェックイン失敗としてカウントされる
5. 目標地点の変更は1アカウントにつき最大3回まで（チャレンジ単位ではなくアカウント単位の累積回数。直前に目標を「自宅」等に変えて失敗を逃れるチートを防止するため）
6. 失敗するたびにデポジット残高が 500 円ずつ減っていく。チャレンジ期間の終了日を迎えるか、残高が 500 円未満になった時点でチャレンジは終了する（後者の場合は端数の残高を没収し即時終了。実際の決済・返金は MVP のスコープ外。詳細は下記）

## MVP（v1）でやること

- ユーザー認証（Google などのソーシャルログイン。Auth.js を想定）
- 目標地点の登録・編集（現地でブラウザの Geolocation API を使って取得した座標をそのまま登録する。地図上でのピン指定は行わない）
- 目標地点の変更（1アカウントにつき最大3回まで。チャレンジをまたいだ累積回数で、上限に達したら以降のチャレンジも含めて変更不可）
- チャレンジ設定：チェックイン期限時刻、チャレンジ期間（開始日〜終了日）、デポジット額（ユーザーが自由に入力。上限・下限のバリデーション値は未確定）。**ペナルティ単価は1失敗あたり500円の固定値**（ユーザー入力ではない）。**期限時刻はチャレンジ開始後は変更不可**（後ろにずらして失敗を逃れる抜け道を防ぐため）
- チェックイン：ブラウザの Geolocation API で現在地を取得し、目標地点から半径 30m 以内であれば距離判定 OK（**30m は暫定値**。GPS 精度の問題があるため下記「未確定事項」を参照）。受付は**当日 4:00（JST）〜期限時刻**の間のみで、それ以外の時間帯のチェックインは無効（前日の夜や深夜の成立を防ぐため）。期限時刻に対する猶予は設けない（厳密判定。1秒でも過ぎたら失敗扱い）
- 失敗日数の算出：DB に「失敗」を書き込む処理は持たず、**表示のたびに「経過日数 − チェックイン成功日数」で動的算出**する
- チャレンジの早期失敗判定：残高（デポジット額 − 失敗回数 × 500円）が500円未満になった時点でチャレンジを「失敗」として即時終了する。**端数の残高は没収し返金しない**。終了後、ユーザーはすぐに新しいチャレンジを作成できる
- チェックイン結果（成功）の記録と、動的算出した失敗回数・残高の表示

## MVP でやらないこと（将来的な拡張候補）

- Stripe 等によるデポジットの実決済・返金連携（v1 では金額計算のみ DB 上で行い、実際のお金は動かさない。下記「将来の Stripe 連携方針」の設計は先に決めておく）
- グループ機能・他ユーザーとの共有
- プッシュ通知／アラーム音などのリマインド機能
- 複数チャレンジの同時進行（v1 は 1 ユーザー1チャレンジを想定）

## 将来の Stripe 連携方針（決定事項・実装は v2 以降）

- 決済時：「デポジット額 + システム利用料（デポジット額の3%、返金対象外）」を合算して決済する
- 返金時：期間満了までチャレンジが継続した場合は「デポジット額 −（失敗回数 × 500円）」を返金する。残高不足による早期失敗の場合は残額を没収し返金しない（0円）。システム利用料は運営側の収益として返金しない
- 注意点：Stripe の決済手数料は日本では概ね3.6%前後のため、3%のシステム利用料だけでは手数料を完全には相殺できない可能性がある。差分は許容する方針とする

## 決定事項（判定ロジック）

- **失敗判定の方式。** DB に失敗を書き込む処理は持たず、表示のたびに「経過日数 − チェックイン成功日数」で動的算出する（日次バッチや遅延書き込みは不要）
- **チェックインの受付開始時刻。** 当日 4:00（JST）固定。期限時刻からの相対計算にすると期限が早朝寄りの場合に前日側へはみ出すため、固定の絶対時刻とする
- **期限時刻の変更可否。** チャレンジ開始後は変更不可（禁止）。目標地点の変更回数上限とは無関係
- **タイムゾーンと日付境界の扱い。** サーバー・DB とも JST 固定で扱う。タイムゾーン変換ロジックは持たない

## 決定事項（ペナルティ）

- **ペナルティ単価。** 1失敗あたり500円の固定値（`lib/config.ts` で管理）。ユーザーが自由入力する対象はデポジット額のみ
- **早期失敗（チャレンジ終了）条件。** 残高（デポジット額 − 失敗回数 × 500円）が500円未満になった時点でチャレンジを「失敗」として即時終了する
- **端数の扱い。** 早期失敗時に残っている端数の残高（0〜499円）は没収し、返金しない
- **早期失敗後。** チャレンジはただちに終了扱いとなり、ユーザーはすぐに新しいチャレンジを作成できる

## 未確定事項（実装着手前に要決定）

**金額まわり**

- デポジット額の入力上限・下限バリデーション値（ペナルティ単価は500円固定となったため、単価側のバリデーションは不要になった）

**その他**

- **GPS 精度の扱い。** Geolocation API は誤差半径を返し、都市部では誤差が数十メートル出る。判定半径 30m のままだと、実際に現地へ行っても失敗する日が出うる。半径の再検討、または誤差が大きい場合に再取得を促す方針が必要
- **位置情報の偽装。** ブラウザの位置情報は開発者ツールで容易に偽装できる。v1 では既知のリスクとして許容するか、何らかの対策を入れるか
- チャレンジの途中離脱・中断時の扱い
- **法務確認（Stripe 連携前に必須）。** 不特定多数から金銭を預かって返還を約束する形態は、出資法の「預り金の禁止」に抵触する可能性がある。「サービス利用料の前払い＋条件付き返金」という建て付けにするなど、実際に金銭を扱う前に専門家への確認が必要

## 技術スタック

- [Bun](https://bun.sh)（パッケージマネージャ兼スクリプトランナー）
- [Next.js](https://nextjs.org) 16 (App Router) + React 19 + TypeScript
- CSS Modules + SCSS（`*.module.scss`）
- MySQL + [Prisma](https://www.prisma.io)
- [Auth.js](https://authjs.dev)（Google 等のソーシャルログイン）
- Vitest（重要なドメインロジックの単体テストのみ）
- （v2 以降）Stripe（デポジットの決済・返金）

開発時の規約・ディレクトリ構成・秘密情報の扱い、および Next.js 16 の破壊的変更に関する注意は [AGENTS.md](AGENTS.md) を参照。
