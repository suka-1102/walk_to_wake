# git / PR

リモートは `origin` (https://github.com/suka-1102/walk_to_wake.git)。

## ブランチ運用（git flow）

| ブランチ | 用途 | 分岐元 | マージ先 |
|---|---|---|---|
| `master` | 本番相当。**直接コミットしない** | — | — |
| `develop` | 開発の統合ブランチ | `master` | — |
| `feature/<内容>` | 通常の機能追加・修正 | `develop` | `develop` |
| `release/<バージョン>` | リリース準備 | `develop` | `master` と `develop` の両方 |
| `hotfix/<内容>` | 本番の緊急修正 | `master` | `master` と `develop` の両方 |

`master` へのマージ元は `release/*` と `hotfix/*` のみ。

## 進め方（AI エージェントと人の分担）

[roadmap.md](roadmap.md) のチェックリストを 1 項目ずつ進める。項目ごとに次を回す。

1. エージェントが、何をどう変えるかを先に一言で出す
2. エージェントが変更し、`bun run lint` と `bun run build` を通す（Phase 0 のみ例外。通らない場合は理由を説明する）
3. エージェントがコミットする。メッセージはチェックリストの行の文言そのまま。`- [ ]` → `- [x]` も同じコミットに含める
4. 人が `git show HEAD` でコミットを確認する
5. 直しがあれば `git commit --amend` か追加コミットで直す
6. 問題なければ次の項目へ進む

**エージェントは人の確認を待たずに次の項目へ進まない。**

## push とマージ

push はフェーズ単位。1 項目ごとには push しない。

1. フェーズのチェックリストを全部終える
2. `feature/*` を push し、`develop` への PR を出す
3. PR の差分でフェーズ全体を確認してからマージする

**push 済みのコミットは amend しない。** 追加コミットで直す。push 前なら amend してよい。

## PR を出す前に

- `bun run lint` と `bun run build` が通ることを確認する
- 要件に関わる変更なら、同じ PR で AGENTS.md の「仕様（決定事項）」も更新する。実装と仕様がズレた状態でマージしない
- 秘密情報の値がコード・コミットメッセージ・PR 本文に含まれていないか確認する

## 書き方

コミットメッセージと PR は日本語。何を変えたかが一文でわかるように書く。
