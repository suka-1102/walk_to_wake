# 画面構成

サイトマップと各画面の役割。スタイルの書き方は [style.md](style.md)、実装の順番は [roadmap.md](roadmap.md)。

## 前提

- **スマホの縦画面を基準に設計する。** PC は縦長レイアウトのまま中央寄せで許容する
- ログイン後の画面は**下部タブバー**で切り替える。タブは4つ

## タブ構成

| タブ | パス | 中身 |
|---|---|---|
| ホーム | `/` | 進行中のチャレンジ（デポジット残高・失敗回数・残り日数）とチェックインへの導線。なければ作成の導線 |
| チェックイン | `/check-in` | 現在地取得 → 精度チェック → 距離・時刻判定 → 結果 |
| 履歴 | `/challenges` | 終了したチャレンジの一覧。各行からチャレンジ詳細へ |
| マイページ | `/mypage` | 保存した目標地点の一覧と削除、利用規約・プライバシーポリシーへの導線、ログアウト |

マイページに保存した目標地点の一覧を置く。専用ページには切らず、タブ内で一覧と削除まで済ませる。

**ホームが出すのは進行中のチャレンジ1件だけ。** 同時に持てるチャレンジは1件なので一覧にはしない。進行中がなければ「チャレンジを作成」ボタンだけを出す。過去のチャレンジは履歴タブから見る。

**日ごとの記録はチャレンジ詳細（`/challenges/[id]`）に置く。** ホームの表示をタップして開く。ホームが出す失敗回数・残高は集計値で、詳細が出す成功・失敗した日の一覧がその内訳にあたる。記録だけを切り出した画面（旧 `/records`）は持たず、タブにも置かない。

**チャレンジ詳細は進行中と終了済みで共用する。** どちらも「集計＋日ごとの記録」で構成が同じで、違うのは終了済みに返金額とシステム利用料が加わる点だけ。画面を分けず表示分岐で扱う。

**履歴はマイページの中ではなくタブに出す。** 終了したチャレンジは使うほど積み上がり、成功・失敗の記録を見返す先になる。設定と同じ引き出しに入れると入口が分かりにくく、ホームが進行中の1件しか出さないぶん、過去分を見る場所は独立していたほうがよい。

## ページ一覧

| パス | 画面名 | 認証 | タブ | 役割 |
|---|---|---|---|---|
| `/login` | ログイン | 不要 | — | Auth.js による Google ログイン。同意の文言と規約・ポリシーへのリンクを置く。ログイン済みなら `/` へリダイレクト |
| `/` | ホーム | 必須 | ✓ | 進行中のチャレンジの状態。なければ作成の導線 |
| `/check-in` | チェックイン | 必須 | ✓ | その日のチェックイン |
| `/challenges` | 履歴 | 必須 | ✓ | 終了したチャレンジの一覧。各行からチャレンジ詳細へ |
| `/mypage` | マイページ | 必須 | ✓ | 保存した目標地点の管理、規約・ポリシーへの導線、ログアウト |
| `/challenges/new` | チャレンジ作成 | 必須 | — | 目標地点（保存済みから選択、または現在地を新規登録）・期限時刻・期間・デポジット額の登録 |
| `/challenges/[id]` | チャレンジ詳細 | 必須 | — | 進行中: 残高・失敗回数・残り日数と、成功・失敗した日の記録。終了済み: それに加えて返金額とシステム利用料 |
| `/terms` | 利用規約 | 不要 | — | 静的ページ。ログイン画面とマイページから遷移 |
| `/privacy` | プライバシーポリシー | 不要 | — | 静的ページ。位置情報の取得目的・保存範囲・削除方法を明記 |
| `not-found` / `error` | エラー | — | — | App Router 規約の `not-found.tsx` / `error.tsx` |

**`/challenges` は複数形のままにする。** 同時に持てるのは1件でも、ユーザーは通算で複数のチャレンジを持つ。`/challenges`（履歴タブ＝一覧）・`/challenges/[id]`（そのうちの1件）・`/challenges/new`（新規作成）が同じ資源の下に並ぶ形が素直で、単数形にすると「1件しか存在しない」という別の意味になり履歴の置き場所がなくなる。

**ログイン後のタブ4つはすべて1階層のパスに置く。** タブから開く画面が `/challenges/current` のようにネストしていると、タブバー左端のホームだけがルート以外になるなど並びが崩れる。履歴の `/challenges` は1階層なのでこの条件を満たす。

**ログインページは `/login`、ルート `/` はログイン後のホーム。** `/login` は Auth.js の `pages.signIn` に指定し、未ログインのアクセスは middleware でここへ寄せる。ルートをログイン画面に使うと、タブバー左端のホームだけがルート以外のパスになってしまう。

**進行中・終了済みを問わず、チャレンジ詳細は `[id]` で開く。** 進行中は1件しかないので ID なしでも引けるが、そのためにパスを分けると同じ画面が2つのパスを持つことになる。

**利用規約とプライバシーポリシーは認証不要。** ログイン前に読めなければ「ログインをもって同意」が成り立たないため、middleware のリダイレクト対象から外す。中身は静的なテキストだけで、DB もクライアント JS も使わない。

**入口はログイン画面とマイページの2箇所。** ログイン画面にはボタン下に同意の文言とリンクを置き、ログイン後はマイページからいつでも読み直せるようにする。フッターは持たない（スマホ縦画面でタブバーと二重になるため）。

**目標地点は保存済みから選ぶか、現在地を新しく登録するかの二択。** 保存が1件もない初回は新規登録だけを出す。新規登録を選んだときだけ位置取得と精度チェックが走り、既存を選んだ場合は登録時に検証済みなので何も測らない。

## 空の状態（進行中のチャレンジがないとき）

| タブ | 表示するもの |
|---|---|
| ホーム | 「チャレンジを作成」ボタン |
| チェックイン | 「ホームからチャレンジを作成してください」の文言のみ |
| 履歴 | 終了したチャレンジが1件もなければ「まだ終了したチャレンジがありません」の文言のみ |
| マイページ | 通常どおり表示する（規約・ポリシーとログアウトは常に使える） |

**チャレンジ作成への導線はホームとチャレンジ詳細（`/challenges/[id]`）の2箇所だけに置く。** チェックインタブにはボタンを置かず、文言だけで済ませる。作成の入口を絞ることで、どこから作成されたかを追う必要がなくなる。

チャレンジ終了直後は詳細画面から次のチャレンジを作成できるため、チェックインタブを空の状態で開く場面はほとんど起きない。そのためタブ移動の1タップは許容する。

## タブバーを出さない画面

**ログイン後の画面はタブバーを出すのが既定。** 出さないのは次の画面だけで、`/challenges/new` や `/challenges/[id]` のようにタブに項目がない画面でもタブバーは出す（タブとして選べるかと、画面下端に出るかは別）。

**タブに項目がない画面では、どのタブも選択中にしない。** `/challenges/new` と `/challenges/[id]` はホームからも履歴からも開くため、どちらか片方を選択中に見せると入口を偽ることになる。タブバーは移動手段としてだけ出す。

- **`/login`** — ログイン前なので出さない
- **`/terms` / `/privacy`** — ログイン前後の両方から開く。読み終えたらブラウザバックで戻る

## 遷移

1. 未ログインでアクセス → `/login` へリダイレクト → ログイン → `/`
2. 進行中のチャレンジがない場合、ホームは空の状態を表示し `/challenges/new` への導線を出す
3. `/challenges/new` で作成完了 → `/`
4. ホーム → 進行中の表示をタップ → `/challenges/[id]`（記録を確認）→ ホームへ戻る
5. ホーム → チェックインタブ → 判定 → ホームに戻る（結果はホームの表示に反映される）
6. 終了条件を満たした時点で `/challenges/[id]` へ遷移し、そこから次のチャレンジ作成へ進める
7. 履歴タブ（`/challenges`）→ 各行 → `/challenges/[id]`

タブ同士は相互に行き来できる。タブバーがあるため、チャレンジ詳細からホームへ戻るのに他の画面を経由する必要はない。

## 画面内で扱うもの（独立ページにしない）

- **位置精度が不足したときの再取得 UI** — `/challenges/new` と `/check-in` の両方で使う状態。共通コンポーネントとして持つ
- **チャレンジ終了の判定** — 専用ページを作らず、ホームを表示した時点で判定して `/challenges/[id]` へ遷移させる
- **成功・失敗した日の記録** — チャレンジ詳細の一部。記録だけの画面は持たない
