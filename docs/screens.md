# 画面構成

サイトマップと各画面の役割。スタイルの書き方は [style.md](style.md)、実装の順番は [roadmap.md](roadmap.md)。

## 前提

- **スマホの縦画面を基準に設計する。** PC は縦長レイアウトのまま中央寄せで許容する
- **全ページに共通のヘッダーとフッターを置く。** ログイン後の画面移動は、ヘッダー左のハンバーガーメニューから行う

## 共通レイアウト

```
┌─────────────────┐
│ Walk to Wake  ☰ │  ← ヘッダー（全ページ）
├─────────────────┤
│                 │
│    ページ本体    │
│                 │
├─────────────────┤
│ 利用規約・ポリシー │  ← フッター（全ページ）
└─────────────────┘
```

### ヘッダー

左にアプリ名、**右にハンバーガーメニュー（☰）**を置く。スマホを片手で持ったとき親指が届くのが画面の右下側で、左上は最も遠い。移動のたびに押すものなので、届く側に寄せる。

**ハンバーガーメニューを出すのはログイン後だけ。** メニューの行き先がすべて認証必須なので、ログイン前に出しても押せる項目がない。`/login`・`/terms`・`/privacy` を未ログインで開いた場合は、ヘッダーはアプリ名だけになる。

### ハンバーガーメニュー

| 項目 | パス | 中身 |
|---|---|---|
| ホーム | `/` | 進行中のチャレンジ（デポジット残高・失敗回数・残り日数）とチェックインへの導線。なければ作成の導線 |
| チェックイン | `/check-in` | 現在地取得 → 精度チェック → 距離・時刻判定 → 結果 |
| 履歴 | `/challenges` | 終了したチャレンジの一覧。各行からチャレンジ詳細へ |
| マイページ | `/mypage` | 保存した目標地点の一覧と削除、アカウント設定、ログアウト |

**開いている画面に対応する項目を選択中として示す。** メニューは一覧として開くため、下部タブバーと違って「どこにいるか」が一目で分からない。ただし `/challenges/new` と `/challenges/[id]` はどの項目にも対応しないので、どれも選択中にしない（→ 後述）。

### フッター

利用規約・プライバシーポリシーへのリンクだけを置く。**全ページに出す**ので、ログイン前後を問わずどこからでも規約を読める。

**著作権表示は持たない。** 個人が自分1人のために作るアプリで、権利を主張する相手がいない。フッターに置くものが増えるほど、規約への導線という本来の役割がぼやける。

## ページ一覧

| パス | 画面名 | 認証 | メニュー | 役割 |
|---|---|---|---|---|
| `/login` | ログイン | 不要 | — | Auth.js による Google ログイン。同意の文言と規約・ポリシーへのリンクを置く。ログイン済みなら `/` へリダイレクト |
| `/` | ホーム | 必須 | ✓ | 進行中のチャレンジの状態。なければ作成の導線 |
| `/check-in` | チェックイン | 必須 | ✓ | その日のチェックイン |
| `/challenges` | 履歴 | 必須 | ✓ | 終了したチャレンジの一覧。各行からチャレンジ詳細へ |
| `/mypage` | マイページ | 必須 | ✓ | 保存した目標地点の管理、アカウント設定、ログアウト |
| `/challenges/new` | チャレンジ作成 | 必須 | — | 目標地点（保存済みから選択、または現在地を新規登録）・期限時刻・期間・デポジット額の登録 |
| `/challenges/[id]` | チャレンジ詳細 | 必須 | — | 進行中: 残高・失敗回数・残り日数と、成功・失敗した日の記録。終了済み: それに加えて返金額とシステム利用料 |
| `/terms` | 利用規約 | 不要 | — | 静的ページ。フッターとログイン画面から遷移 |
| `/privacy` | プライバシーポリシー | 不要 | — | 静的ページ。位置情報の取得目的・保存範囲・削除方法を明記 |
| `not-found` / `error` | エラー | — | — | App Router 規約の `not-found.tsx` / `error.tsx` |

**ホームが出すのは進行中のチャレンジ1件だけ。** 同時に持てるチャレンジは1件なので一覧にはしない。進行中がなければ「チャレンジを作成」ボタンだけを出す。過去のチャレンジは履歴から見る。

**日ごとの記録はチャレンジ詳細（`/challenges/[id]`）に置く。** ホームの表示をタップして開く。ホームが出す失敗回数・残高は集計値で、詳細が出す成功・失敗した日の一覧がその内訳にあたる。記録だけを切り出した画面（旧 `/records`）は持たない。

**チャレンジ詳細は進行中と終了済みで共用する。** どちらも「集計＋日ごとの記録」で構成が同じで、違うのは終了済みに返金額とシステム利用料が加わる点だけ。画面を分けず表示分岐で扱う。

**履歴はマイページの中ではなくメニューの独立項目に置く。** 終了したチャレンジは使うほど積み上がり、成功・失敗の記録を見返す先になる。設定と同じ引き出しに入れると入口が分かりにくく、ホームが進行中の1件しか出さないぶん、過去分を見る場所は独立していたほうがよい。

**`/challenges` は複数形のままにする。** 同時に持てるのは1件でも、ユーザーは通算で複数のチャレンジを持つ。`/challenges`（履歴＝一覧）・`/challenges/[id]`（そのうちの1件）・`/challenges/new`（新規作成）が同じ資源の下に並ぶ形が素直で、単数形にすると「1件しか存在しない」という別の意味になり履歴の置き場所がなくなる。

**メニューの4項目はすべて1階層のパスに置く。** `/challenges/current` のようにネストした項目が混ざると、階層の深さが揃わず並びとして読みにくい。履歴の `/challenges` は1階層なのでこの条件を満たす。

**ログインページは `/login`、ルート `/` はログイン後のホーム。** `/login` は Auth.js の `pages.signIn` に指定し、未ログインのアクセスは middleware でここへ寄せる。

**進行中・終了済みを問わず、チャレンジ詳細は `[id]` で開く。** 進行中は1件しかないので ID なしでも引けるが、そのためにパスを分けると同じ画面が2つのパスを持つことになる。

**利用規約とプライバシーポリシーは認証不要。** ログイン前に読めなければ「ログインをもって同意」が成り立たないため、middleware のリダイレクト対象から外す。中身は静的なテキストだけで、DB もクライアント JS も使わない。

**規約・ポリシーの入口はフッターに一本化する。** 全ページにフッターが出るので、マイページに別途リンクを置くと同じ行き先への入口が二重になる。ログイン画面だけは、同意の文言とセットで見せる必要があるためボタン下にもリンクを置く。

**初回の位置情報取得の前に説明を出し、そこにもプライバシーポリシーへのリンクを置く。** `/challenges/new` の新規登録と `/check-in` で、ブラウザの許可ダイアログが出る前に「目標地点との距離判定にのみ使う」「判定に使った現在地は保存しない」を短く示す。出すのは初回だけで、2回目以降は出さない。判断が必要なのは許可を出す瞬間だけで、毎朝の操作に挟むと読まれないまま邪魔になるため。初回かどうかは `localStorage` で持つ（同意の記録ではなく表示制御なので DB には持たない）。

**目標地点は保存済みから選ぶか、現在地を新しく登録するかの二択。** 保存が1件もない初回は新規登録だけを出す。新規登録を選んだときだけ位置取得と精度チェックが走り、既存を選んだ場合は登録時に検証済みなので何も測らない。

## マイページの中身

上から次の順で並べる。すべて `/mypage` の中で完結させ、下位ページには切らない。

| 区分 | できること |
|---|---|
| 保存した目標地点 | 登録済みの地点を一覧し、不要になったものを削除する |
| アカウント設定 | 表示名の変更、アカウントの削除 |
| — | ログアウト |

**保存した目標地点の削除を置くのは、位置情報を必要以上に持ち続けないため。** プライバシーポリシーに「削除の方法」を書く以上、ユーザーが自分で消せる場所が要る。削除しても進行中・終了済みのチャレンジには影響しない（チャレンジは選んだ時点の名前と座標を写して持つ）。

**表示名は Google プロフィールの名前を初期値とし、アプリ内だけで上書きできる。** Google 側のアカウント名は変更しない。

**アカウント削除は確認を挟んだうえで、保存した目標地点・チャレンジ・チェックインの記録をすべて消す。** 消したら復元できないことと、進行中のチャレンジがあってもデポジットは戻らないことを削除前に明示する。削除後はログアウトして `/login` へ戻す。専用ページは作らず、マイページ内の確認ダイアログで完結させる。

**保存した目標地点をアカウント設定の下にまとめるかは未決。** 今は別々の区分として並べる（→ [roadmap.md](roadmap.md) の「保留中の判断」）。

## 空の状態（進行中のチャレンジがないとき）

| 画面 | 表示するもの |
|---|---|
| ホーム | 「チャレンジを作成」ボタン |
| チェックイン | 「ホームからチャレンジを作成してください」の文言のみ |
| 履歴 | 終了したチャレンジが1件もなければ「まだ終了したチャレンジがありません」の文言のみ |
| マイページ | 通常どおり表示する（アカウント設定とログアウトは常に使える） |

**チャレンジ作成への導線はホームとチャレンジ詳細（`/challenges/[id]`）の2箇所だけに置く。** チェックイン画面にはボタンを置かず、文言だけで済ませる。作成の入口を絞ることで、どこから作成されたかを追う必要がなくなる。

チャレンジ終了直後は詳細画面から次のチャレンジを作成できるため、チェックイン画面を空の状態で開く場面はほとんど起きない。そのためメニューを開いて移動する手間は許容する。

## ヘッダー・フッターの出し分け

**ヘッダーとフッターは全ページに出す。** 認証の有無で変わるのはハンバーガーメニューだけ。

| 画面 | ヘッダー | ハンバーガー | フッター |
|---|---|---|---|
| ログイン後の全画面 | ✓ | ✓ | ✓ |
| `/login` | ✓ | — | ✓ |
| `/terms` / `/privacy`（未ログイン） | ✓ | — | ✓ |
| `/terms` / `/privacy`（ログイン後） | ✓ | ✓ | ✓ |

**メニューに項目がない画面では、どの項目も選択中にしない。** `/challenges/new` と `/challenges/[id]` はホームからも履歴からも開くため、どちらか片方を選択中に見せると入口を偽ることになる。メニューは移動手段としてだけ出す。

## 遷移

1. 未ログインでアクセス → `/login` へリダイレクト → ログイン → `/`
2. 進行中のチャレンジがない場合、ホームは空の状態を表示し `/challenges/new` への導線を出す
3. `/challenges/new` で作成完了 → `/`
4. ホーム → 進行中の表示をタップ → `/challenges/[id]`（記録を確認）→ ホームへ戻る
5. ホーム → メニュー → チェックイン → 判定 → ホームに戻る（結果はホームの表示に反映される）
6. 終了条件を満たした時点で `/challenges/[id]` へ遷移し、そこから次のチャレンジ作成へ進める
7. メニュー → 履歴（`/challenges`）→ 各行 → `/challenges/[id]`
8. フッター → `/terms` / `/privacy` → ブラウザバックで戻る

メニューの4項目は相互に行き来できる。ヘッダーが全ページにあるため、チャレンジ詳細からホームへ戻るのに他の画面を経由する必要はない。

## 画面内で扱うもの（独立ページにしない）

- **位置精度が不足したときの再取得 UI** — `/challenges/new` と `/check-in` の両方で使う状態。共通コンポーネントとして持つ
- **チャレンジ終了の判定** — 専用ページを作らず、ホームを表示した時点で判定して `/challenges/[id]` へ遷移させる
- **成功・失敗した日の記録** — チャレンジ詳細の一部。記録だけの画面は持たない
- **アカウント削除の確認** — マイページ内のダイアログ。`/mypage/delete` のようなパスは作らない
