# 画面構成

サイトマップと各画面の役割。スタイルの書き方は [style.md](style.md)、実装の順番は [roadmap.md](roadmap.md)。

## 前提

- **スマホの縦画面を基準に設計する。** PC は縦長レイアウトのまま中央寄せで許容する
- ログイン後の画面は**下部タブバー**で切り替える。タブは4つ

## タブ構成

| タブ | パス | 中身 |
|---|---|---|
| ホーム | `/` | デポジット残高・失敗回数・残り日数。チェックインへの導線 |
| チェックイン | `/check-in` | 現在地取得 → 精度チェック → 距離・時刻判定 → 結果 |
| 記録 | `/records` | 進行中のチャレンジで成功した日・失敗した日の一覧 |
| マイページ | `/mypage` | 保存した目標地点の一覧と削除、履歴・利用規約・プライバシーポリシーへの導線、ログアウト |

マイページに保存した目標地点の一覧を置く。専用ページには切らず、タブ内で一覧と削除まで済ませる。

**記録タブが扱うのは進行中のチャレンジだけ。** 終了したチャレンジの記録は履歴（`/challenges/[id]`）で見る。タブの役割を「今のチャレンジの進捗確認」に絞り、マイページの履歴と重複させない。

## ページ一覧

| パス | 画面名 | 認証 | タブ | 役割 |
|---|---|---|---|---|
| `/login` | ログイン | 不要 | — | Auth.js による Google ログイン。同意の文言と規約・ポリシーへのリンクを置く。ログイン済みなら `/` へリダイレクト |
| `/` | ホーム | 必須 | ✓ | 進行中のチャレンジの状態 |
| `/check-in` | チェックイン | 必須 | ✓ | その日のチェックイン |
| `/records` | 記録 | 必須 | ✓ | 進行中のチャレンジで成功・失敗した日の一覧 |
| `/mypage` | マイページ | 必須 | ✓ | 保存した目標地点の管理、履歴・規約・ポリシーへの導線、ログアウト |
| `/challenges/new` | チャレンジ作成 | 必須 | — | 目標地点（保存済みから選択、または現在地を新規登録）・期限時刻・期間・デポジット額の登録 |
| `/challenges` | 履歴 | 必須 | — | 終了したチャレンジの一覧。マイページから遷移 |
| `/challenges/[id]` | チャレンジ結果 | 必須 | — | 終了したチャレンジの結果。失敗回数・返金額・システム利用料と、成功・失敗した日の一覧 |
| `/terms` | 利用規約 | 不要 | — | 静的ページ。ログイン画面とマイページから遷移 |
| `/privacy` | プライバシーポリシー | 不要 | — | 静的ページ。位置情報の取得目的・保存範囲・削除方法を明記 |
| `not-found` / `error` | エラー | — | — | App Router 規約の `not-found.tsx` / `error.tsx` |

**ログイン後のタブ4つはすべてトップレベルのパスに置く。** タブは「今の状態を見る場所」であってチャレンジ資源の子ではないため、`/challenges/` 配下はチャレンジ作成と終了済みの閲覧だけに使う。

**ログインページは `/login`、ルート `/` はログイン後のホーム。** `/login` は Auth.js の `pages.signIn` に指定し、未ログインのアクセスは middleware でここへ寄せる。ルートをログイン画面に使うと、タブバー左端のホームだけがルート以外のパスになってしまう。

**進行中はルート、終了済みは `[id]` で分ける。** 同時に持てるチャレンジは1件なので、進行中のものは ID を URL に出さずに引ける。

**利用規約とプライバシーポリシーは認証不要。** ログイン前に読めなければ「ログインをもって同意」が成り立たないため、middleware のリダイレクト対象から外す。中身は静的なテキストだけで、DB もクライアント JS も使わない。

**入口はログイン画面とマイページの2箇所。** ログイン画面にはボタン下に同意の文言とリンクを置き、ログイン後はマイページからいつでも読み直せるようにする。フッターは持たない（スマホ縦画面でタブバーと二重になるため）。

**目標地点は保存済みから選ぶか、現在地を新しく登録するかの二択。** 保存が1件もない初回は新規登録だけを出す。新規登録を選んだときだけ位置取得と精度チェックが走り、既存を選んだ場合は登録時に検証済みなので何も測らない。

**チャレンジ結果の画面は終了直後と履歴で共用する。** 終了条件（期間満了・早期失敗）を満たした時点で `/challenges/[id]` へ遷移させ、履歴からも同じ画面を開く。満了と早期失敗の違いは同一画面内の表示分岐で扱う。

## 空の状態（進行中のチャレンジがないとき）

| タブ | 表示するもの |
|---|---|
| ホーム | 「チャレンジを作成」ボタン |
| チェックイン | 「ホームからチャレンジを作成してください」の文言のみ |
| 記録 | 「まだ記録がありません」の文言のみ |
| マイページ | 通常どおり表示する（履歴とログアウトは常に使える） |

**チャレンジ作成への導線はホームと結果画面（`/challenges/[id]`）の2箇所だけに置く。** チェックインタブと記録タブにはボタンを置かず、文言だけで済ませる。作成の入口を絞ることで、どこから作成されたかを追う必要がなくなる。

チャレンジ終了直後は結果画面から次のチャレンジを作成できるため、チェックインタブを空の状態で開く場面はほとんど起きない。そのためタブ移動の1タップは許容する。

## タブバーを出さない画面

- **`/login`** — ログイン前なので出さない
- **`/challenges/new`** — 入力途中で他タブへ移動されると入力内容が失われる。
- **`/challenges/[id]`** — チャレンジ終了直後と履歴の両方から開く。タブから直接開くものではない
- **`/terms` / `/privacy`** — ログイン前後の両方から開く。読み終えたらブラウザバックで戻る

## 遷移

1. 未ログインでアクセス → `/login` へリダイレクト → ログイン → `/`
2. 進行中のチャレンジがない場合、ホームは空の状態を表示し `/challenges/new` への導線を出す
3. `/challenges/new` で作成完了 → `/`
4. ホーム → チェックインタブ → 判定 → ホームに戻る（結果はホームの表示に反映される）
5. 終了条件を満たした時点で `/challenges/[id]` へ遷移し、そこから次のチャレンジ作成へ進める
6. `/mypage`（マイページ）→ `/challenges`（履歴）→ 各行 → `/challenges/[id]`

タブ同士は相互に行き来できる。タブバーがあるため、ホームへ戻るのに履歴や一覧を経由する必要はない。

## 画面内で扱うもの（独立ページにしない）

- **位置精度が不足したときの再取得 UI** — `/challenges/new` と `/check-in` の両方で使う状態。共通コンポーネントとして持つ
- **チャレンジ終了の判定** — 専用ページを作らず、ホームを表示した時点で判定して遷移させる
